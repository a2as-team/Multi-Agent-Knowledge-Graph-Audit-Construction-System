# **📘 Detailed Context of the Proposed Architecture**

*(Based on “Proposed Architecture (Course Based).pdf”)*

Proposed Architecture (Course B…

The proposed system is a **multi-agent architecture** designed to build a **Knowledge Graph (KG)** from both structured and unstructured data using specialized agents. It follows a workflow-oriented approach, where each agent has a clear role, and together they create:

1. A **Graph Construction Plan** (for structured data)

2. A **Knowledge Extraction Plan** (for unstructured data)

3. A final **Knowledge Graph**, built using an automated Construction Tool

At the top of the hierarchy sits the **Knowledge Graph Agent**, which orchestrates the entire pipeline.

---

# **1\. High-Level System Overview**

*(Page 1\)*

Proposed Architecture (Course B…

The system contains **three major agent branches**:

### **A. Structured Data Agent Branch**

* Works with **CSV files**

* Breaks down into three sub-agents:

  * **User Intent Agent**

  * **File Suggestion Agent**

  * **Schema Proposal Agent**

* Produces output: **Graph Construction Plan**

### **B. Unstructured Data Agent Branch**

* Works with **Markdown files**

* Includes:

  * **User Intent Agent** (unstructured version)

  * **File Suggestion Agent**

  * **Entity & Fact Type Proposal Agent**

* Produces output: **Knowledge Extraction Plan**

### **C. GraphRAG Agent**

* Specialized inference agent

* Uses the Knowledge Graph to answer questions via retrieval strategies

All branches feed into the **Knowledge Graph Construction Tool**, which builds the final KG automatically.

* Manages the **overall interaction** with the user

# **4\. Structured Data Sub-Agents**

*(Page 4\)*

Proposed Architecture (Course B…

### **1\. User Intent Agent**

* Conversational

* Determines what the user wants to achieve with the structured data

* Helps set the direction (e.g., “import employee performance dataset into graph”)

### **2\. File Suggestion Agent**

* Tool-use

* Analyzes available CSV files

* Suggests which ones are relevant based on the user’s intent

### **3\. Schema Proposal Agent**

* The most critical sub-agent

* Works in a **“critic pattern”** (iterative refinement)

* Proposes an appropriate graph schema (nodes, relationships, properties)

* Improves the schema iteratively until approved

### **Output: Graph Construction Plan**

Defines:

* Approved schema

* Steps for turning CSV files into a graph

* Rules for mapping columns → node/relationships

# **5\. Unstructured Data Sub-Agents**

*(Page 5\)*

Proposed Architecture (Course B…

### **1\. Entity & Fact Type Agent**

* Tool-use agent

* Collaborates with the user to determine:

  * Entity types to extract from markdown

  * Fact types (relationships or attributes)

### **Output: Knowledge Extraction Plan**

Includes:

* Approved entity types

* Approved fact templates

* Extraction instructions for markdown sources

This ensures a consistent and constrained extraction strategy.

# **6\. Knowledge Graph Construction Tool**

*(Page 6\)*

Proposed Architecture (Course B…

This is the **executor** of the entire pipeline.

It performs:

### **1\. Graph Construction (Structured Data)**

* Reads the construction rules from the Graph Construction Plan

* Converts CSV data into nodes, relationships, and properties

### **2\. Knowledge Extraction (Unstructured Data)**

* Loops through Markdown files

* Chunks content

* Extracts entities and facts following the Knowledge Extraction Plan

* Connects extracted entities to existing KG nodes

Essentially, **this tool operationalizes all the plans generated by the agents**.
